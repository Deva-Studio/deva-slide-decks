01

What a CLI is,
and how one is built

The parts every command-line tool shares, and the one that matters most for a design system.

The basics

A program you run by typing its name

A CLI (command-line interface) runs in a terminal. It takes what you type, asks for anything missing, and then does the work: here, creating a whole project.

Flags

02

The setup interview
as a decision tree

Fewer questions, asked in the right order, with a recommendation where one is better.

The interview

Gate each question on the answers before it

  • Ask only what changes the output. If no file depends on an answer, drop the question
  • Gate questions. Someone building a feature never sees "Who will see it?"
  • Recommend a choice and say why, using what they've already told you
  • Give every question a flag, so the same tree runs in CI
Answer the questions · the tree updates

Try changing the first answer to Feature or Contribution

The interview

Recommend a choice, and say why

A blind menu

? Starting layout
❯ App shell
  Form flow
  Blank page
 

Every option looks equally right, so people pick the first one or guess.

A recommendation with a reason

? Starting layout
❯ App shell (Recommended)
  Participants should see something that feels like the product
  Form flow
  Blank page

The reason comes from an earlier answer. People can still choose differently, and now they know the trade-off.

// The recommendation is a rule that sits next to the question, so it can be reviewed like any design decision
recommend: (a) => a.audience === 'participants'
  ? ['shell', 'Participants should see something that feels like the product']
  : ['blank', 'Nothing to remove when sketching an idea'],

The scaffold

Each answer maps to what gets scaffolded

Every answer adds, swaps or skips files. Nothing is generated "just in case".

  • Every project gets the tokens, components and lint rules
  • Content picks realistic mock data or placeholders
  • Layout copies one template built from your components
  • Agent writes that agent's rules, plus the hooks where it supports them
Answer the questions · new files are highlighted

03

Keeping the AI agent
inside the system

The scaffold doesn't stop at files. It sets up the agent that will keep building in them.

The agentic layer

The scaffold sets up the agent too

Rules

CLAUDE.md, AGENTS.md or .cursor/rules: which tokens and components to use, and what never to write.

A guardrail hook

Runs before every edit lands, and blocks off-system styles and components.

A session-start check

Compares what's installed with what's published, and tells the agent what's new.

Rules are advice an agent can forget. Hooks are code that always runs.

checkout-study/
├── CLAUDE.md              rules
├── AGENTS.md              rules for any agent
├── .claude/
│   ├── settings.json      registers the hooks

Guardrail

A hook that blocks off-system code

// .claude/settings.json
"PreToolUse": [{
  "matcher": "Edit|Write",
  "hooks": [{ "type": "command",
    "command": "node .claude/hooks/ds-guard.mjs" }]
}]
// .claude/hooks/ds-guard.mjs
const { tool_input } = JSON.parse(await readStdin());
const code = tool_input.new_string ?? tool_input.content ?? '';
const problems = [
  ...rawColours(code).map((c) =>
    `Raw colour ${c}. Use a token: ${tokenFor(c)}`),
  ...rawElements(code).map((el) =>
    `<${el}> found. Use <${componentFor(el)}>`),
];
if (problems.length) {
  console.error(problems.join('\n'));
  process.exit(2); // blocks the edit; stderr tells the agent the fix
}

Staying current

A session-start check nudges toward updates

Prototypes outlive the version they were made with. When a session starts, the hook compares versions and gives the agent a short note.

// .claude/hooks/ds-check.mjs · registered under "SessionStart"
const installed = installedVersion('@your-ds/components');
const latest = await publishedVersion('@your-ds/components');
if (installed !== latest) {
  console.log(`Components ${installed} installed · ${latest} available`);
  console.log(`New: ${await newComponents(installed, latest)}`);
}
if (scaffoldVersion() < latestScaffold()) {
  console.log('Update with: npx create-ds-prototype update');
}
// SessionStart output is added to the agent's context

It nudges and never blocks. Updating stays the team's call.
